# LightForge changelog

This is a concise source-change history. Published APKs and their exact evidence
are listed in [GitHub Releases](https://github.com/CyberBASSLord-666/LightForge/releases).
A source version or an entry here does not itself establish publication. The
[pre-cleanup changelog](https://github.com/CyberBASSLord-666/LightForge/blob/07511f5544b688c657773dce8a29d8d31ba68cb1/CHANGELOG.md)
retains detailed historical development notes and their original limitations.

## 2.3.1 — repeated bass articulation and inference experiments

Recover repeated same-pitch bass attacks from short-window harmonic trough and
restart evidence instead of merging them into a single held note. Rebuild bass
phrases, strengths and semantic events from the recovered source-clock
boundaries. Preserve accompaniment-mixture provenance and the existing limits on
isolated-instrument claims. Focused fixtures cover repeated harmonic notes,
decaying plucks, sustained sub-bass, smooth tremolo, kicks, noise and read seams.

Add a source-bound GAME WASM batch-specialization comparison with complete stage
fingerprints, raw tensor parity, unrounded notes, alternating fresh processes and
separate inference/initialization/CPU/RSS observations. The measured candidate
preserved exact output but was slower and remains disabled. A separate native
Deux geometry experiment changed output bytes and was also rejected. Original
models, precision, contexts, steps and production inference settings remain.

## 2.3.0 — musical expression and inference engineering

Add tonal novelty and evidence-supported irregular phrasing to default analysis.
Recommend validated vocal expression and recurring motifs for new projects;
allow compatible saved shows to enable expression without rerunning models.
Preserve selected vocal/bass attacks, historical settings and reversible edits.
Keep oversized optional recurrence from failing a completed long-show analysis.

Add repeated, exact-output native execution comparisons and a separate GAME
backend prototype with strict intermediate-output comparison. The prototype is
not enabled in the app. Retain original model fidelity and the independent
strict performance target. Publication still requires exact-source host/Android
verification and the original update-signing identity.

This source also includes bounded automatic renderer recovery from valid saved
progress and the repository maintenance below. Publication status is recorded
in GitHub Releases, independently of this source history.

### Repository maintenance

Remove verified redundant source/APK transfer pieces, the completed import
machinery, obsolete snapshot/checklist documents and two one-shot recovery
workflows. Consolidate current guides, correct release-status drift, simplify
ignore rules and add a tested repository/documentation hygiene check. No app
version, model, runtime behavior, published APK, signing control or retained QA
evidence is changed by this maintenance work.

## 2.2.4 — published bounded analysis update

Add guarded native Balanced MDX execution with complete-pair compatibility
fallback, bounded WASM lifetimes and reused transform buffers. Share execution
ownership, retire failed native allocations before fallback, save/report durable
checkpoints promptly and improve paused-preview/native-crash recovery. Preserve
model weights, quality settings and original update identity. The
[numerical qualification](qa/release-2.2.4/NUMERICAL_QUALIFICATION.md) retains its
spectral exceptions and limited scope; it is not universal parity evidence.

## 2.2.3 — unpublished development precursor

Update native ONNX Runtime to pinned 1.25.1 without changing Studio weights or
batch geometry. Add persisted native execution markers, confirmed-crash
compatibility selection, bounded tombstone decoding and native crash/recovery
instrumentation. These changes were included in 2.2.4; this entry is not a
separate published-release claim.

## 2.2.2 — diagnostics and renderer recovery

Add local bounded Android/JavaScript traces and user-controlled diagnostic export
to Downloads or the system save dialog. Include available process-exit context
without automatic upload or attached music/project payloads. Make renderer
cleanup tolerate detached/retired WebViews and defer recovery UI until foreground.
Keep native Studio quality, background execution and verified-passage Resume.

## 2.2.1 — native Studio and resumable analysis

Move Studio separation to pinned native CPU inference with bounded batches and
reusable buffers. Bind passage/stage checkpoints to source, settings, version and
execution lineage. Add elapsed/reused-work reporting, safer WebView teardown,
screen-off/cancel/resume instrumentation and streaming APK staging. The retained
[Deux comparison](qa/release-2.2.1/DEUX_RUNTIME.md) covers one short host excerpt,
not a full-song or phone forecast.

## 2.2.0 — background analysis

Give an Android foreground service ownership of analysis/composition, durable
single-job state, progress notifications and cancellation. Add user-controlled
notification/battery settings, bounded wake locks, timeout cleanup and Android
lifecycle coverage. No endless restart loop or automatic reboot resume.

## 2.1.0 — Studio workspaces and neural singing

Bundle full-context Deux separation and GAME Large with pinned provenance and
licenses. Add source-clock voice caches, speech/bleed guards, Compose/Music/
Outputs/Review workspaces and a zoomable musical score. Introduce original-key
publication from a qualified CI candidate without private signing keys in Actions.

## 2.0.0 — Precision Studio

Add editable voice/bass cues, independent part timing, passage loops,
collision-aware role routing and final-frame synchronization review. Preserve
checked legacy snapshots and project-isolated edits. Centralize runtime version
metadata and compatible-signing checks. No unmeasured detection-accuracy claim.

## 1.6.0 — separated voice and musical expression

Add offline vocal separation, singing/speech evidence on isolated voice, acoustic
articulation/hold estimates and accompaniment-based bass tracking. Add listening
layers, emphasis presets, passage guides and constrained movement phrasing.
Preserve checked older arrangements. The original APK and checksum remain in
[the historical release](releases/v1.6.0/README.md).

## 1.5.0 — singing and bass-note detail

Add independent singing evidence, bass-note/held-note timing, role emphasis and
seekable analysis lanes. Keep uncertainty and instrumental fallback visible,
retain other musical roles and preserve checked 1.4 frames.

## 1.4.0 — learned rhythm and durable projects

Add full/compact Beat This! analysis, repeated sections, phrase motifs, A/B
editing, Undo/Redo, loops and adaptive rendering. Store compressed checked frame
snapshots; add streaming export, transactional saves and import/export recovery.

## 1.3.0 — structure-aware composition

Improve local tempo, meter, attack timing, phrases and active-audio detection.
Introduce dedicated light planning and movement arrivals governed by preparation,
travel, recovery and command budgets rather than a repeating beat pattern alone.

## 1.2.0 — individual outputs and Highland mapping

Add the documented output catalog, per-output inclusion, light/RGB cues and
independent moving-part tracks. Validate movement prerequisites and return cues.
Correct lamp surfaces/shared channels, remove unsupported fog outputs and keep
outer-beam ramping optional pending vehicle confirmation. Per-lens behavior,
Dance cadence, optics and latency remain estimates.

## 1.1.0 — Highland 3D preview

Replace the projected vehicle with a bundled WebGL 2 Highland model and renderer.
Add black materials, lighting, shadows, lamp glow, stage/camera choices, orbit,
zoom and cabin cutaway. Keep preview state tied to exported commands; geometry
and movement remain visual estimates, not physical validation.

## 1.0.1 — audio transport and playback repair

Fix double-seek PCM range handling behind “Audio data ended unexpectedly.” Validate
WAV ranges, distinguish transport faults, rebuild damaged derived analysis audio
and retain common-format Android imports. Export normalized stereo PCM WAV with
matching FSEQ basenames; preserve original export audio when a very long recording
requires a smaller in-app playback representation.
