# Full-source GAME session reuse experiment

`tools/benchmark_game_session_reuse.py` is a separate host-only research
collector. It never edits the app or substitutes a candidate into the existing
full-source collector. Its evidence schema is
`lightforge.game-session-reuse-experiment.v1`.

The declared question is exact **default versus reuse within one provider**.
The default provider matrix is CPU/ALL and deterministic heavy-only CUDA/BASIC.
Each has default/reuse lifecycle arms and fresh plain/captured/profiled JVMs:
12 processes in total. `--variants cpu_all` explicitly restricts the matrix to
six CPU processes and requires no GPU JAR or CUDA runtime. A CPU-only result
cannot qualify CUDA. Prior archives remain references; this collector does not
substitute them for fresh controls or calculate a timing ratio.

All arms retain the original float32 graphs, eight diffusion steps, source
language, 12-second core, 2-second halo, seeds, sample slices and unrounded
notes. A 64-second source has six passages and 72 graph calls per process.
The bounded non-silent-input restriction is inherited from the existing
full-source experiment. Every captured/profiled passage retains all 16 raw
tensors through the unchanged capture helper.

The candidate is generated by `session_reuse_candidate.py` from the pinned
production source. Five sessions persist until final worker close; RunOptions
and tensors remain per-call. Default snapshots retain the original creation and
retirement behavior. Both arms use one Java engine object. Cancellation/close
may block in the reuse candidate. It remains prohibited for Android lifecycle
or UI threads, regardless of any successful host result. The independent
fault harness is a separate gate, not replaced by successful inference.

## Lifetime trace binding

`GameSessionReuseTrace.java` instruments only the profiled twin. It brackets
original synchronous calls under a single owner, records source-bound passage
identity, graph, session identity and per-session call ordinal, and issues a
unique profiling prefix when each session is constructed. The completed trace
marker file is written only after final close. Default yields 30 completed
session traces for six passages; reuse yields five lifetime traces.

The validator checks the complete passage schedule, exact original graph order,
serial marker ownership, session construction order/counts, and every graph
call. It independently orders non-overlapping ORT `model_run` intervals within
each session and binds them to that session's explicit call ordinals. All ORT
kernel events must lie wholly within exactly one ORT model-run interval. The
entire trace set must have one process identity and one original-call thread.
Five-graph/12-call provider placement is revalidated for each reconstructed
passage; 72 calls are required for a complete 64-second source.

Java marker nanoseconds and ORT profile timestamps use different clock origins.
They are never compared or subtracted. No approximate clock calibration, run
tag assumption, invented per-passage closed trace, or numerical tolerance is
used. The ordinal mapping relies on the hash-bound, single-owner synchronous
wrapper; its source is part of the evidence.

## Gates and status

Each arm requires exact plain/captured unrounded notes and exact
captured/profiled raw tensors and unrounded notes. Observer disagreement rejects
the experiment. Each provider then compares every default/reuse captured
passage without a tolerance. A numerical mismatch remains a diagnostic with
`WITHIN_PROVIDER_EQUIVALENCE_UNPROVEN`; it never grants timing admission.

Source, model, runtime JAR, input, generated Java snapshots, patches, compiled
classes, runtime probes, logs, raw output and trace hashes are preserved and
rechecked. GPU qualification additionally inventories the loaded CUDA libraries
and their observed versions. The parent keeps fresh-process timeouts and kills
the complete JVM process group on interruption/failure. The standalone collector
converts SIGTERM to a Python interruption so this cleanup also runs on ordinary
process termination; its interrupted receipt remains unqualified. Output directories must
be new. Partial failures remain on disk.

A successful exact comparison yields `COMPLETE_DIAGNOSTIC`, with
`withinProviderRawAndUnroundedParityProven=true` for the explicitly selected
providers only. `qualityApproved`, `benchmarkTimingAdmitted`, `target75Proven`,
`releaseAuthorized`, Android and full-vocal/whole-analysis speedup flags all
remain false. No repeated timing protocol is implemented here.

## Commands

Use actual verified public/synthetic full PCM and provenance. First compile and
probe every selected mode without inference:

```sh
python3 tools/benchmark_game_session_reuse.py \
  --toolchain /path/to/pinned-toolchain --models /path/to/original-game \
  --input /path/to/public-full.f32 --input-provenance /path/to/input-provenance.json \
  --variants cpu_all --check-readiness --output /new/readiness
```

Then use a different fresh output directory and omit `--check-readiness` for the
six-process CPU qualification. Omit `--variants cpu_all` only when the complete
pinned CUDA runtime is ready for both provider matrices. Do not infer a CUDA
result from Java API compilation against a CPU JAR.

Focused source/trace tests:

```sh
python3 -m unittest discover -s tests -p 'test_game_session_reuse.py' -v
```

These tests exercise adversarial bindings and trace partitioning. They do not
replace actual native inference, fault/lifecycle qualification, independent
archive verification, musical-quality gates or production verification.
