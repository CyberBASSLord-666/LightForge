# Recorded analysis snapshot contract

`baseline-{demo,sample}-music.json` and `current-{demo,sample}-music.json` are
committed analysis outputs used by the choreography/FSEQ regression tests. They
are not audio fixtures and are never regenerated by `npm test` or release CI.

The baseline pair was captured with the frozen 1.2.0 analyzer by
`capture-baseline.cjs`; the current pair was captured with the production 1.3.0
analyzer by `capture-analysis.cjs`. `recorded-fixture-contract.json` pins each
snapshot's byte length and SHA-256, while
`tests/recorded-music-fixture-contract.test.cjs` also checks its essential
analysis schema and event counts. A missing, truncated, corrupt, or substituted
snapshot is a release-gate failure.

The demo source is bundled. The historical `Sample.wav` source is external and
is not required to run the planner regression: the approved recorded JSON
snapshot is the test input. Do not replace it with generated music, downloaded
audio, or a new analysis result merely to make a test pass. Recapturing a
snapshot requires the approved source audio, its provenance in
`audio-metadata.json`, the appropriate baseline/current analyzer, and an
intentional reviewed update to the contract.

If a complete repository checkout is missing these JSON files, restore the
committed `qa/music-1.3.0` directory before running the release suite. This is
unrelated to the separately licensed MUSDB excerpts prepared under
`qa/release-1.6.0/fixtures` for source-separation verification.
